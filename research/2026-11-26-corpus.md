# Corpus: Bash tool commands of one workstation, 72 hours

Source: every Claude Code transcript file of one workstation, main sessions (108 files) and sub-agents
(3,192 files), modified in the 72 hours before 2026-11-26 00:25 UTC. The window selects files by
modification time, so a long-lived file adds its older records too. From each record:
`.message.content[] | select(.type == "tool_use" and .name == "Bash") | .input.command`, made
unique by tool-use id (524,195 records, 331,797 unique ids).

Measured with throwaway programs in the session scratch directory, not kept: a `jq` extraction,
and a Rust probe that parsed every command with five parsers (`docs/design.md` § 5). The
structural counts below come from brush-parser's tree (331,747 commands) and tree-sitter-bash's
for the 50 that brush refused. Counts are by AST, not by text search. Command text stays out of
this file (`AGENTS.md` § Rules); only counts and generic shapes are written here.

One thread, 85 s for all five parsers, run outside `slot` as a measurement. All four bash parsers agree on
acceptance for 327,844 commands; 43 fail in all four.

Most common refusals, by shape: brush: unterminated backquote 14, error at end of input 7, near
`;` 5. tree-sitter-bash: a statement starting with `;` 105, a redirect followed by `|` 41, a
heredoc in a redirected statement 19. yash-syntax: process substitution unsupported 1,033,
unclosed `${` 521. conch-parser: unexpected `(` 2,522.

On commands that both brush-parser and tree-sitter-bash accept, their trees disagree on the count
of `||` 264 times, on pipe tails 2,014 times and on stage counts 1,359 times. tree-sitter-bash
nests `a && b 2>&1 | c` as `(a && b 2>&1) | c` (checked on hand-written inputs; the same
grammar behaviour is why `b10x guard bash` moves a list's trailing redirect to its last command).
